# 02 — Repository Layout, Tooling, Conventions, and Quality Gates

## 1. Repository root

The code repository is created inside this folder (the folder containing `ralph.yml`). The repository root is
the same directory; specs, prompts, and plans live alongside the code and are committed.

```
.
├── ralph.yml                       # Ralph orchestrator configuration (hats, gates)
├── MASTER_PROMPT.md                # Universal instructions for every Ralph iteration
├── PROMPT.md                       # Generated per phase by scripts/ralph/run_phase.sh (MASTER_PROMPT + phase prompt)
├── AGENTS.md                       # Operational guide: commands, conventions, gotchas (kept current by agents)
├── README.md                       # Human guide to this package and the platform
├── specs/                          # Normative specifications (this directory)
├── prompts/                        # Phase prompts phase-00.md … phase-20.md
├── plan/                           # Phase checklists phase-00.md … phase-20.md (agents tick boxes)
```

## 4. Python conventions

- `ruff` config: line length 110, target `py312`, rules `E,F,W,I,N,UP,B,A,C4,DTZ,T20,RET,SIM,TID,ARG,PTH,ERA,PL,TRY,RUF,ASYNC,S`
  (ignore `S101` in tests, `PLR0913` for FastAPI endpoints). `ERA` forbids commented-out code.
- `mypy`: `strict = true`, `plugins = ["pydantic.mypy", "sqlalchemy.ext.mypy.plugin"]` is NOT used (SQLAlchemy 2.0
  typed `Mapped[]` instead), `warn_unreachable = true`.
- Async everywhere on I/O paths. Never call blocking I/O inside the event loop; CPU-bound work (PDF parsing,
  ONNX VAD batch) runs in `asyncio.to_thread` or a process pool as specified per module.
- Time: always timezone-aware UTC `datetime` (`va_common.time.utcnow()`); never naive datetimes.
- IDs: UUIDv7 (`uuid_utils.uuid7()`) for all primary keys. Public prefixed forms: tools `TL-<uuid>`, knowledge bases
  `KB-<uuid>`, prompts `PT-<uuid>`. Serialization/parsing lives in `va_common.ids`.
- Money: integer **micro-dollars** (`1 USD = 1_000_000`) in `BIGINT` columns; never floats. API presents dollars as
  decimal numbers rounded to 6 places.
- Errors: raise `va_common.errors.AppError(code, message, http_status, details)`; the API layer renders the envelope
  (`31-error-catalog.md`).
- Logging: `structlog` JSON; every log line in a call context binds `org_id`, `call_id`, `turn_index`. Never log
  secrets, raw audio, full phone numbers in non-debug logs (mask as `+1415***1234`), or transcripts unless
  `LOG_TRANSCRIPTS=true` in local env.
- Settings: one `Settings` class per service extending `va_common.settings.BaseServiceSettings`.
- Dependency injection: FastAPI `Depends` for request-scoped resources; a `Container` dataclass built at startup
  holds clients (DB engine, Redis, HTTP clients, vendor clients) and is passed explicitly to non-HTTP code.
- Tests: `pytest-asyncio` in `auto` mode; integration tests use testcontainers (Postgres with pgvector image,
  Redis, ClickHouse, MinIO); Temporal tests use `WorkflowEnvironment.start_time_skipping()`.

## 5. TypeScript conventions

- `strict`, `noUncheckedIndexedAccess`, `exactOptionalPropertyTypes`. ESLint flat config with
  `typescript-eslint` strict-type-checked, `eslint-plugin-react-hooks`, `eslint-plugin-jsx-a11y`. Prettier.
- API types for the dashboard are generated from `openapi/openapi.json` with `openapi-typescript` into
  `apps/dashboard/src/lib/api/schema.d.ts`; requests go through `openapi-fetch`.
- Vitest for unit tests, Testing Library for components, Playwright for e2e.

> Decision (2026-10-25): how `.env.example` mirrors this table is fixed as follows, and
> `scripts/tests/test_env_example.py` (parsers in `scripts/env_spec.py`) fails when either side drifts.
> The table declares 105 names in 104 rows — the `` `S3_ACCESS_KEY_ID` / `S3_SECRET_ACCESS_KEY` `` row declares two
> names and splits its dev-value cell on `/` positionally — of which 104 are literal keys and one
> (`LOG_LEVEL_<COMPONENT>`) is a name template. Dev-value cells fall into three classes: **literal** (the cell starts
> with a backtick; the required value is the first backticked span, so `` `localhost:8100` (tunnel host for live
> tests) `` means `localhost:8100` and ``` `console` in local, `json` elsewhere ``` means `console`), **empty** (the
> cell is `empty` or starts with `empty `), and **free** (prose such as `64 random hex chars` or
> ``created by `scripts/telnyx_bootstrap.py` ``). `.env.example` then carries, in table order, one
> `NAME=value  # comment` line per literal key with a non-empty trailing comment; literal-class values appear
> verbatim, double-quoted when they contain spaces (`EMAIL_FROM`); empty-class values are assigned empty;
> free-class values are only required to be present, and the four secret-shaped ones (`SECRET_KEY`,
> `STREAM_TOKEN_SECRET`, `LOCAL_MASTER_KEY`, `API_KEY_PEPPER`) carry distinct, visibly synthetic 64-hex dev fillers
> with a comment pointing at `openssl rand -hex 32`, so the file never holds real entropy or a real credential.
> Name templates are not assignments: they appear only inside a comment line that contains the templated name.
> Standalone comment lines (section headers, preamble) and blank lines are unconstrained. Parity is enforced through
> `make test` only; §9 deliberately lists no separate env gate.

## 7. Git and commits

- Conventional Commits: `feat(engine): …`, `fix(media): …`, `test(api): …`, `docs(specs): …`, `chore(ci): …`.
- One plan task per commit; message footer `Task: P07-T12`.
- Never commit secrets; `.env` is gitignored; `.env.example` is committed.
- Ralph checkpoints commit automatically every `checkpoint_interval` iterations; agents still commit after each
  approved task.

## 8. Definition of Done for any task

1. Code complete per the referenced spec sections, including error paths.
2. Tests written first or alongside; new tests fail without the change and pass with it.
3. `make check` passes locally (all gates in §9).
4. If the task touches an end-to-end flow listed in `30-testing-and-evals.md` §5, `make e2e` passes.
5. `AGENTS.md` updated if a new command, gotcha, or convention emerged.
6. Plan checkbox ticked with a one-line evidence note (`- [x] P05-T03 … — tests: 14 passed; e2e: outbound_basic ok`).

### 9.1 `scripts/check_no_placeholders.py` behaviour

- Scans tracked files under `apps/`, `packages/`, `sdks/`, `infra/`, `scripts/` (excluding `node_modules`, `.venv`,
  `dist`, `build`, generated `schema.d.ts`, `openapi/openapi.json`, lockfiles, and binary files).
- Fails on (case-insensitive where sensible): `TODO`, `FIXME`, `XXX`, `HACK`, `TBD`, `placeholder` (except inside
  the literal HTML/JSX attribute `placeholder=` and the CSS pseudo-element `::placeholder`), `NotImplementedError`,
  `implement me`, `lorem ipsum`, `your-api-key`, `example.com` in non-test source, Python function/method bodies
  consisting only of `pass` or `...` (detected via `ast`; allowed only in `Protocol` classes, abstract methods
  decorated with `@abstractmethod`, and exception class bodies that have a docstring), TS functions whose body is
  empty `{}` (via regex on `=> {}` / `) {}` excluding `catch {}` which is separately forbidden — empty catch is
  always a failure), `console.log` in TS source (allowed in scripts and on lines ending with the marker comment `// va-allow-console`), `print(` in Python source outside `scripts/`
  and CLI modules.
- Prints `path:line: rule: excerpt` for each finding; exit 1 if any.
- Has its own tests in `scripts/tests/test_check_no_placeholders.py`.

## 10. Bland-compatibility conventions

- Public API paths mirror Bland (`/v1/calls`, `/v1/pathway`, `/v2/batches/create`, …). Field names are
  snake_case exactly as Bland documents them, even where our internal model names differ.
- Both `Authorization: Bearer <key>` and `Authorization: <key>` are accepted. `x-api-key` is ignored (Bland parity).
- Legacy Bland-style success bodies (`{"status":"success", ...}`) are returned by the endpoints Bland defines
  that way; newer resources use the `{data, errors}` envelope. See `31-error-catalog.md` for the exact matrix.
